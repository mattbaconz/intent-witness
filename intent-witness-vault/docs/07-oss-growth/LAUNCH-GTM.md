# Launch and Go-To-Market

## Launch principle

**The result sells the tool.** Lead with a before/after, not a manifesto.

## Launch asset stack

Minimum:

1. one undeniable hero comparison;
2. 10–20 second loop/video;
3. same model + same brief + same repo claim, verifiably documented;
4. short install command;
5. GitHub README with benchmark caveat;
6. two or three additional domain examples;
7. public eval methodology.

## Hero narrative

```text
Coding agent: “Done.”
Intent Witness: “No. The primary workflow is buried under generic metrics.”
Agent revises structure.
Intent Witness: PASS.
```

The demo should visibly show a structural change, not just prettier colors.

## Channels

Priority likely:

- Discord communities for AI coding/ADEs/frontend/open source;
- X / developer social media;
- Reddit communities where tool sharing is allowed;
- Hacker News / Show HN once the repo is credible;
- GitHub discovery/awesome lists;
- community showcases in Cursor/Claude/Codex ecosystems;
- short YouTube demo;
- dev.to/blog deep-dive after benchmark data exists.

## Message hierarchy

### Hook
“AI coding agents keep declaring generic UI done.”

### Mechanism
“Intent Witness gives them an independent design reviewer.”

### Proof
“Same model. Same brief. Review forced a structural revision.”

### Action
“Install it / try it on your ugliest generated screen.”

## Avoid

- “revolutionary AI design platform” language;
- claiming first-ever without exhaustive evidence;
- spam-posting identical messages;
- fake benchmark screenshots;
- insulting users for liking conventional UI;
- pretending human designers are obsolete.

## Growth experiment

Challenge:

> **Give Intent Witness your ugliest AI-generated dashboard.**

Users submit repo/screenshot/brief. Turn good cases (with permission) into fixtures/demos.

This creates both marketing material and product research.

## Launch readiness gate

Do not heavily market until:

- install works cleanly;
- one ADE loop is reliable;
- reviewer output is consistently specific;
- README has at least one reproducible comparison;
- known limitations are honest;
- no obvious copyright/licensing problems in demo assets.
