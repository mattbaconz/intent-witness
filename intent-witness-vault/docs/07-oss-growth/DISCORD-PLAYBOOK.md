# Discord Marketing Playbook

## Why Discord

The target audience already congregates in communities around:

- Cursor;
- Claude Code;
- Codex;
- OpenCode;
- Kiro/Antigravity/Windsurf;
- frontend engineering;
- shadcn/component ecosystems;
- indie hacking;
- open-source AI tooling.

Discord can produce fast qualitative feedback and user-submitted test cases.

## Rule zero

**Do not spam.** Only post where showcases/self-promotion are permitted, and adapt the post to the server.

One thoughtful post with an undeniable demo is worth more than identical blasts across 30 servers.

## Best post structure

1. One-line pain/hook.
2. GIF/video or before/after image.
3. One-line mechanism.
4. Install/repo link.
5. Ask for hard test cases.

Example tone (adapt, do not paste everywhere):

```text
I got tired of coding agents declaring this kind of dashboard “done,” so I made the builder hand the rendered UI to an independent design reviewer before shipping.

Same model + same brief below. Intent Witness rejected the first structure because the actual workflow was buried under generic metrics, then forced a deeper revision.

It’s OSS. I want ugly/hard generated UIs to break it—send me one.
```

## Community-specific angle

### Cursor server/community
Lead with native subagent/browser workflow and easy install.

### Claude Code
Lead with independent reviewer/skill orchestration and compare against frontend-design skill honestly.

### Codex
Lead with portable Agent Skill + subagent/MCP potential.

### Frontend/design communities
Lead with evidence, false-positive safeguards, and “not a universal beauty score.”

### Indie hackers
Lead with before/after output and no-designer workflow.

## Feedback questions

Ask users:

- Did it catch something you actually cared about?
- Which finding was wrong?
- Did it force too much redesign?
- Would you run it again on the next screen?
- What builder/model did you use?

Do not only ask “can you star the repo?”

## Discord funnel

```text
Demo post
  ↓
GitHub install
  ↓
user tries on real UI
  ↓
shares failure/success
  ↓
fixture or showcase
  ↓
better Intent Witness
```

## Reputation risk

Because “AI slop” is emotionally loaded, avoid acting as taste police. The product should be curious and evidence-based: “this decision looks generic *because…*” rather than “your UI is garbage.”
